# مانیکس — رفع خطاهای رایج

## پنل بالا نمی‌آید

**Set PANEL_PASSWORD…**: رمز تنظیم نشده، کوتاه‌تر از ۱۲ کاراکتر یا همان متن نمونه است. رمز مخصوص خودت را در Variables تنظیم و تغییرات را Deploy کن.

**Attach a Railway Volume…**: Volume وجود ندارد یا Mount Path با DATA_DIR یکسان نیست. هر دو `/data` باشند. اضافه کردن پوشهٔ data به GitHub جای Volume را نمی‌گیرد.

**Permission denied**: لاگ entrypoint را ببین. سرویس باید بتواند مالکیت ریشهٔ Volume را اصلاح کند؛ `RAILWAY_RUN_UID=0` و Dockerfile خود پروژه را استفاده کن. image سپس به کاربر غیر-root تغییر می‌کند.

**Java پیدا نشد**: پروژه با Railpack/Python تنها اجرا شده و image چند-Java ساخته نشده. Builder را Dockerfile بگذار. تغییر Start Command به `java -jar` هم پنل را از کار می‌اندازد.

**HTTP 502 یا healthcheck failure**: PORT و پورت مقصد دامنه باید یکسان باشند؛ پیش‌فرض 8080. healthcheck `/healthz` است، نه 25565. لاگ Build و Deploy را جدا بررسی کن.

## پنل روشن است، بازی وصل نمی‌شود

1. آیا یک هسته نصب شده و EULA پذیرفته شده؟
2. آیا در کنسول `Done` آمده یا سرور هنوز starting است؟
3. آیا TCP Proxy پورت داخلی 25565 دارد؟ HTTP Domain بازی Minecraft را عبور نمی‌دهد.
4. آیا آدرس عمومی **با پورت تصادفی Proxy** را وارد کرده‌ای؟
5. آیا نسخهٔ Minecraft کلاینت با سرور هماهنگ است؟ این پروژه ViaVersion را خودکار نصب نمی‌کند.
6. اگر موددار است، آیا کلاینت مودها/لودر سازگار دارد؟
7. اول hostname اصلی Railway Proxy را امتحان کن؛ بعد DNS اختصاصی را بررسی کن.

## سرور بلافاصله بسته می‌شود

- **137 / -9** ممکن است کمبود RAM یا قطع اجباری سرویس باشد؛ سهمیه و مصرف Railway را ببین. heap را کمتر کن یا RAM سرویس را ارتقا بده. فقط heap را تا کل سهمیه بالا نبر.
- **UnsupportedClassVersionError**: Java نامناسب. Java را روی Auto بگذار یا نسخهٔ مناسب انتخاب کن. metadata نسخهٔ جدید ممکن است Java25 لازم داشته باشد.
- **Mod resolution / missing dependency**: لودر، نسخه Minecraft یا وابستگی غلط است. کنسول معمولاً نام مود مشکل‌دار را می‌گوید. مود را با بازی خاموش غیرفعال کن.
- **EULA**: گزینه را خودت بخوان و تأیید کن. آپلود کردن eula.txt جای تأیید مالک در پنل را نمی‌گیرد.
- نسخهٔ قدیمی/مود قدیمی ممکن است حتی با حداقل Java اعلام‌شده به نسخهٔ خاصی از لودر/Java نیاز داشته باشد؛ این پنل همهٔ ترکیب‌های تاریخی را تست نکرده.

## نصب نسخه خطا می‌دهد

- نبود بیلد `STABLE` Paper خطای عمدی و امن است؛ نسخهٔ دیگری انتخاب کن یا بعداً دوباره تلاش کن. به نسخهٔ دیگری بی‌خبر سوییچ نمی‌شود.
- برای NeoForge فقط stable installer عرضه می‌شود؛ beta ممکن است در لیست نباشد.
- خطای SHA/checksum: فایل نصب نمی‌شود. دوباره تلاش کن؛ بررسی هش را برای رفع خطا خاموش نکن.
- APIها ممکن است قطعی/Rate limit یا تغییر ساختار داشته باشند؛ لاگ نام منبع را نشان می‌دهد.
- Forge/NeoForge تا ۱۵ دقیقه برای نصاب فرصت دارند. در زمان نصب ری‌دیپلوی نکن.
- کمبود فضای Volume: قبل از دانلود/Extract/بکاپ، فضای کافی برای فایل‌های موقت هم لازم است. ZIP فشردهٔ کوچک ممکن است حجم بازشدهٔ بزرگ داشته باشد.
- بازگشت به نسخهٔ قدیمی‌تر دنیا باید جدا تأیید شود و ممکن است واقعاً دنیا را خراب کند؛ بهتر است دنیای تازه بسازی یا بکاپ همان نسخه را Restore کنی.

## سیو در بازی دیده نمی‌شود

`level.dat` باید داخل پوشهٔ تعیین‌شده در `level-name` باشد. فایل‌منیجر فقط server root را نمایش می‌دهد؛ مسیر صحیح معمولاً `world/level.dat` است، نه `world/world/level.dat`. پوشه‌های Nether/End در Paper و Vanilla ممکن است چیدمان متفاوت داشته باشند. قبل از تغییر دستی بکاپ بگیر.

## بکاپ، Extract یا Restore خطا می‌دهد

- بکاپ Manix با «وارد کردن بکاپ» وارد می‌شود؛ ZIP معمولی دنیا از فایل‌منیجر و Extract.
- بازیابی فقط با بازی خاموش. روی Volume جدید ابتدا همان type/version بکاپ را نصب کن.
- ZIP رمزدار، symlink، مسیر مطلق، `..` و حجم بازشدهٔ بالاتر از MAX_ARCHIVE_MB رد می‌شود.
- فایل‌ها فقط داخل server root قابل‌دسترسی‌اند؛ `.sqlite3` پنل عمداً نمایش داده نمی‌شود.
- بکاپ‌های داخل Volume در برابر پاک شدن خود Volume محافظت ندارند. همیشه یک نسخه بیرون نگه دار.
- یک عملیات هم‌زمان مجاز است. خطای 409 معمولاً یعنی بازی روشن است یا عملیات قبلی هنوز اجرا می‌شود.

## ورود/دامنهٔ جدید مشکل دارد

- صفحه را Refresh کن؛ دامنه‌های مختلف cookie مشترک ندارند، باید در دامنهٔ جدید دوباره وارد شوی.
- پنل باید HTTPS اصلی Railway باشد. origin و API نسبی‌اند؛ آن را در سایت دیگری iframe نکن.
- تغییر PANEL_PASSWORD نشست‌ها را باطل می‌کند. بعد از ۵ تلاش اشتباه، همان IP حدود ۱۵ دقیقه محدود می‌شود.
- اگر reverse proxy دیگری جلوی Railway گذاشته‌ای، Host و scheme اصلی را درست منتقل کن. FORWARDED_ALLOW_IPS را فقط برای proxyهای مورداعتماد استفاده کن.

## مصرف فضای بازی زیاد شده

بکاپ‌های دستی، Safety، before-version و before-extract نگه داشته می‌شوند و خودکار پاک نمی‌شوند. بکاپ‌های غیرضروری را پس از دانلود امن از جدول پاک کن. JARهای غیرفعال در disabled-addons هم جا می‌گیرند و در بکاپ بازی هستند. runtimeهای قدیمی در engines برای Restore نگهداری می‌شوند؛ با CLI فقط موارد غیر فعال و غیر لازم برای بکاپ‌ها را حذف کن.


## رمز UI بعد از Redeploy عوض نمی‌شود / فراموش کرده‌ام

این رفتار عمدی است: مقدار Environment قبلی bootstrap است و UI password را در هر Deploy برنمی‌گرداند. برای Reset، `PANEL_PASSWORD` را به مقدار واقعاً متفاوت جدید عوض و Redeploy کن؛ session/keyها باطل می‌شوند. صرف Save همان Variable یا همان رمز قبلی Reset نیست. MFA باقی می‌ماند.

## کد ۲FA رد می‌شود

ساعت گوشی و کانتینر درست باشد، time-based/6 digit/30 sec/SHA1 و Secret همان enrollment اخیر. کد مصرف‌شده دوباره مجاز نیست؛ کد تأیید setup هم مصرف شده، برای ورود فوری کد جدید بگیر. recovery code نیز یک بار؛ فقط یک خط/کد وارد کن. بعد از پنج شکست ممکن است ۱۵ دقیقه محدود شوی. با نداشتن گوشی/recovery، مالک provider موقتاً `MANIX_RESET_2FA=true` و Redeploy؛ سپس **فوراً حذف/false و Redeploy**. ایمیل پروفایل reset نمی‌فرستد.

## API Key 403 می‌دهد ولی در مرورگر وارد هستم

Authorization بر cookie اولویت دارد و عمداً به دسترسی مالک fallback نمی‌کند. Scope route را بررسی کن؛ account/کلید/MFA/Task/runtime/addons/پک مدیریت با Bearer مجاز نیست. برای دانلود خروجی World از exports، `backups.read` هم لازم است. token منقضی/لغوشده 401 می‌دهد؛ raw token از metadata قابل‌بازیابی نیست، کلید جدید بساز.

## تغییر پورت، اتصال بازی را قطع کرد

پورت داخلی جدید در مانیکس باید با Target Port TCP Proxy Railway و mapping Compose یکسان باشد. پورت عمومی تغییر مستقلی دارد و لزوماً 25565 نیست. نوشتن proxy host/port در فرم، تنظیم provider را عوض نمی‌کند. اول خود hostname:public-port را تست کن، سپس DNS/SRV.

## World ZIP وارد نشد یا پوشهٔ اشتباه ساخته شد

ZIP سیو باید level.dat در ریشه یا یک پوشهٔ دنیای اصلی داشته باشد؛ چند دنیا/backup کامل از مسیر جدا وارد می‌شوند. نام تازه، بدون slash/.. و نام رزروشده مثل mods لازم است. انتخاب دنیا فقط level-name است. برای ساختار Paper/Vanilla و Nether/End ممکن است تبدیل دستی لازم باشد؛ panel repair NBT ندارد. قبل از فعال‌سازی فایل و نسخه را بررسی کن.

## پک در Minecraft دانلود نمی‌شود

pack.mcmeta در ریشه و pack format سازگار با کلاینت، URL HTTPS عمومی واقعی، بازی بعد از تغییر Restart و resource-pack-sha1 درست. دامنهٔ نمونه/localhost برای بازیکن بیرونی کار نمی‌کند. لینک `/packs/id.zip` را بیرون از login تست کن؛ باید فقط ZIP پک را بدهد. after migration دامنه را دوباره فعال کن. required/prompt در MCهای قدیمی ممکن است پشتیبانی نشوند. client download واقعی این محیط تست نشده است.

## Task اجرا نشد / missed یا claimed دیدم

خود سرویس باید روشن و sleeping خاموش، timezone IANA معتبر، زمان یک‌باره آینده، EULA و runtime آماده باشد. busy Job تا آزاد شدن gate صبر می‌کند؛ بیش از ده دقیقه دیرکرد replay نمی‌شود و missed می‌شود. claim قبل از اجرا ثبت می‌شود؛ قطع Deploy/Job می‌تواند نوبت را از دست بدهد. Job/کنسول را ببین؛ این سیستم exactly-once نیست. برای یک‌بارهٔ گذشته زمان آینده را ویرایش کن. Taskها از Restore بکاپ بازی برنمی‌گردند؛ SQLite همان Volume آن‌ها را نگه می‌دارد.

## JVM flag یا JAR دستی کار نمی‌کند

فقط flags فهرست مجاز؛ یک GC، Xmx/Xms از heap، ZGC با Java 17+ در این پنل. flag قانونی هم ممکن است روی Java/engine انتخابی مناسب نباشد؛ حذفش کن و کنسول را ببین. Spigot باید JAR **سرور اجرایی** ساخته‌شده با روش معتبر باشد، نه BuildTools/installer/plugin JAR. همهٔ کلاس‌های یک JAR دستی از روی header کلاس اصلی تضمین نمی‌شوند؛ Java/dependencies مناسب را بررسی کن. custom نوع سازگاری مود/پلاگین حدسی ندارد.

## copy/move یا حذف گروهی شکست خورد

بازی خاموش، Job قبلی تمام، مقصد پوشهٔ موجود و بدون فایل هم‌نام، مبدأ symlink نباشد و کپی داخل خودش نباشد. حداکثر ۲۰۰ انتخاب و حجم کافی با staging/free-space reserve. حذف گروهی ابتدا backup می‌گیرد؛ با دیسک پر بدون backup حذف خطرناک انجام نمی‌دهد. متن Job را بررسی کن؛ rollback معمولی جای تضمین ضد قطع ناگهانی سرویس نیست. قبل از کار مهم offline backup داشته باش.


## Job نصب هسته خطا داد ولی نسخهٔ فعال تغییر کرد

ممکن است ثبت هسته در دیتابیس انجام شده باشد و نوشتن Audit یا نتیجهٔ Job بعد از آن شکست بخورد. مانیکس در این حالت JAR فعال را برای cleanup حذف نمی‌کند. صفحهٔ «نسخه‌ها» و فهرست هسته‌های نصب‌شده را تازه کن، فایل/نسخهٔ فعال و لاگ Volume را بررسی کن و قبل از تکرار نصب، وضعیت واقعی را ببین. خطای قبل از ثبت هسته، اشاره‌گر قبلی و JARهای quarantineشده را برمی‌گرداند؛ در خطای بعد از commit، هستهٔ تازه حفظ می‌شود. این تفاوت در تست‌های مرز commit پوشش داده شده است.
